# 日本語の文章は yomiyasu を通してから出す

日本語の文章を作ったら、人に見せる前、保存する前に、必ず yomiyasu を通す。AI が書いた文章に出やすい言い回しを、出す前に直すため。2026-11-28 にユーザーが決めた。

yomiyasu の本体は https://github.com/nanaism/yomiyasu で、このリポジトリでは `.claude/skills/yomiyasu/` に入っている。

## 対象

人が読むために新しく書く、または書き直す日本語の文章すべて。

- サイトに載せる文章（`src/content` の記事、画面の文言、title と description）
- サイトの外に出す文章（X などへの投稿文、告知文、GitHub の Issue やコメント）
- リポジトリに残す文書（`doc/`、`README.md`、`.claude/rules/` の規則）
- ユーザーに承認を求めるために見せる文面の案

対象でないもの。

- 日本語以外の文章（英語の投稿文など）。yomiyasu は日本語の規則しか持たない
- コード、コマンド、設定ファイル、テストの名前
- Beads のタスク本文、コミットメッセージ、会話での短い受け答え。平易に書くことは同じだが、lint までは求めない

## 通し方

1. yomiyasu スキルを呼び、その手順で推敲する（意味と条件を変えずに直す）。
2. 文章をファイルに書き出し、lint を終了コード 0 で通す。

   `python -I .claude/skills/yomiyasu/scripts/yomiyasu_lint.py <ファイル> --doc-type <種類> --reader general --fail-on warn`

3. 候補が出たら直して、もう一度流す。直すと意味が変わる候補は、直さずに理由を添えて報告する。

保存しない文章（投稿文の案など）は、スクラッチパッドか `tmp/` に一時ファイルを作って lint する。

`--doc-type` は文章の種類に合わせる。

| 文章 | `--doc-type` |
|---|---|
| 記事（`src/content`） | `article` |
| SNS の投稿文、告知文、紹介文 | `promo` |
| メール、チャット、Issue のコメント | `mail` |
| 設計書、規則、手順書 | `manual` |
| 提案、検討をまとめた文書 | `proposal` |
| 項目を箇条書きで並べる記録（`doc/growth-knowhow.md` の実験の記録など） | `incident` |

## 見せるとき

- ユーザーに文面の案を見せるときは、yomiyasu を通したあとのものを見せ、通したことを一言添える。
- 文字数に上限のある投稿文（X など）は、lint のあとに文字数も数えてから見せる。

## ほかの規則との関係

- `src/content` の日本語記事は `npm test` でも lint を強制している（`yomiyasu-lint.md`）。この規則はテストが見ていない文章にも同じ手順を広げる。
- サブエージェントに文章を書かせるときは、依頼にこの規則を書き、lint の結果を報告させる。
