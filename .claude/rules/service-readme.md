# サービスの基本情報を README.md の「サービス情報」節に書く

このプロジェクトが提供するサービスの基本情報は、ルートの `README.md` の「サービス情報」節に表で書く。何のサービスで、いまどの段階にあり、どこで動いていて、どう監視しているかを、README を開いた人がすぐ分かるようにするため。複数のサービスを運用していると公開日や監視の設定を探し回ることになるので、一か所に集める。

## 置く場所

- `README.md` のタイトル（最初の見出し）の直後に置く。タイトルの下に短い説明文があれば、その後ろ。
- 他のどの節よりも前に置く。

## 書く内容

「サービス情報」節に、次の 2 列（項目、内容）の表を書く。項目は次の 8 つを、この順で、すべて載せる。

| 項目 | 内容 |
|---|---|
| サービス名 | サービスの名前。リポジトリ名と違ってよい |
| 段階 | `企画`、`開発中`、`公開中`、`休止`、`終了` のいずれか 1 つ |
| GitHub リポジトリ | このリポジトリの URL |
| URL | 利用者がアクセスする URL。公開前で決まっていれば予定の URL、決まっていなければ「未定」。終了していれば最後に公開していた URL |
| インフラ | 使っている外部サービス（ホスティング、データベース、認証、監視など）の名前を読点で並べる。`README.md` に「インフラ」節があれば、その表にあるサービスと一致させ、用途や設定の場所はその節に任せる |
| 説明 | 何を誰に提供するサービスかを 1〜2 文で |
| 公開日 | 初めて `公開中` になった日。`YYYY-MM-DD` で書く。公開前は「未公開」 |
| UptimeRobot monitor ID | UptimeRobot でこのサービスを監視しているモニターの ID（数字）。ステータスページの ID とは別のもの。複数あれば読点で並べる。監視していなければ「なし」 |

### 段階の意味

- `企画`: 作ると決めたが、まだ開発を始めていない。
- `開発中`: 開発しているが、利用者にはまだ公開していない。
- `公開中`: 利用者に公開して運用している。
- `休止`: 公開を一時的に止めている。再開する可能性がある。
- `終了`: 公開をやめ、再開しない。

### 例

```markdown
## サービス情報

| 項目 | 内容 |
|---|---|
| サービス名 | Foo Notes |
| 段階 | 公開中 |
| GitHub リポジトリ | https://github.com/example/foo-notes |
| URL | https://foo-notes.example.com/ |
| インフラ | Vercel、Supabase、Cloudflare、UptimeRobot |
| 説明 | 個人向けのメモ共有サービス。Markdown で書いたメモを URL で共有できる |
| 公開日 | 2026-01-15 |
| UptimeRobot monitor ID | 800123456 |
```

- 空欄にしない。該当しないものは「なし」、決まっていないものは「未定」と書く。
- 分からない項目は推測で埋めず、ユーザーに確認する。
- 秘密の値は書かない。UptimeRobot の API キーや、URL に含まれる認証用のトークンが当たる。monitor ID は秘密ではないので書いてよい。

## 更新するとき

次の変更をしたら、同じ作業の中で「サービス情報」節も更新する。ユーザーから README の更新を頼まれていなくても行う。

- サービスの名前や、提供するものが変わった: `サービス名` と `説明` を直す。
- URL が決まった、変わった: `URL` を直す。
- 外部サービスを使い始めた、やめた: `インフラ` を直す。「インフラ」節があれば、同じ作業でそちらも直す。
- UptimeRobot のモニターを作った、変えた、消した: `UptimeRobot monitor ID` を直す。
- 段階が変わった: `段階` を直す。初めて `公開中` にしたときは `公開日` も入れる。

段階、公開日、monitor ID のように、リポジトリの中からは変化が読み取れないものは、ユーザーが伝えたときに直す。作業の内容と表が食い違っていると気づいたら（例: 段階が `開発中` なのに本番環境へ公開する作業をしている）、表を勝手に直さず、ユーザーに確認する。

## 節がないとき

- `README.md` に「サービス情報」節がなければ作る。分からない項目はユーザーに確認してから書く。
- サービスの URL や公開状況などを一覧にした節が既にあれば（「基本情報」「About」など）、新しく作らずにその節に表を置く。
- `README.md` が日本語以外で書かれていれば、見出しと項目名の言語をそれに合わせる。
- `README.md` がなければ作る。
